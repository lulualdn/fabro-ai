# One idea per slide, and speaker rhythm

Slides are not a document. They support someone talking. Each slide carries one idea the audience grasps in three seconds.

## Plan before designing
1. Write the talk as a list of sentences, one per slide. Each sentence is a claim ("Our deliveries are late on Mondays"), not a topic ("Deliveries").
2. Use the claim as the slide title. The body proves it: one number, one picture, one chart, or three short points.
3. Count: about one slide per minute of talk.

## Rhythm
- **Alternate slide types** so the eye gets rest: statement → evidence → picture → number → statement.
- **Section breaks** every 4–6 slides: a quiet slide with only the part's name and number.
- **Build up**: when a list matters, show it over three slides, adding one item each time, rather than one dense slide.
- **Open strong, close with the ask**: first slide states why it matters; last content slide says what you want (decision, action, remember this).

## Slide types to mix
- Statement: one sentence, very large, lots of space.
- Big number: the figure huge, one line below.
- Evidence: chart with its title as the claim.
- Picture: full-bleed image, one caption.
- Three points: maximum three lines of up to eight words.
- Quote: a real quote with the person's name.

## Technique: size for the back row
```css
.slide h2 { font-size: 56px; line-height: 1.1; }
.slide p, .slide li { font-size: 30px; }
```
If text needs to be under 24px to fit, split the slide.

## Avoid
- Paragraphs on slides, more than three bullets, reading the slide aloud.
- Titles like "Introduction", "Results", "Conclusion" without a claim.
- The same layout twenty times.
- A logo and footer on every slide eating space.

## Self-check
1. Can you read the deck's story from the titles alone?
2. Does each slide hold one idea?
3. Is any text smaller than 24px?
4. Do slide types vary every two or three slides?
5. Does the last slide ask for something?
