Write a guide (write_guide) when the next time would otherwise cost the same effort again:
- a command sequence that finally worked here (with the exact commands and paths);
- a website's quirks (where the button is, what blocks automation);
- the user's project conventions or deploy steps.
Good guide: a name like `deploy-netlify-site`, a one-line `when`, 5-15 lines of verified steps, the pitfalls.
Never: secrets, passwords, tokens (write "<your token>"), guesses you did not verify.
If a guide you read was wrong or incomplete, fix it with update_guide.
